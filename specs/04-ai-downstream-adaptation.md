## 1. Objective and non-goals

### Objective
This spec defines the bounded, AI-authored downstream adaptation engine of the Centralized AI SDLC Orchestrator and its portfolio preset: the three config-driven helper CLIs `src/lab-studio-drift.mjs`, `src/bump-studio-revision-pins.mjs` and `src/verify-immutable-gates.mjs`; the runtime behaviour of the three `mode: "ai-adaptation"` `gh-aw` workflows that SPEC-01 renders into `.github/workflows/cascade-ai-copilot-lab.md`, `.github/workflows/cascade-ai-pipeline-showcase.md` and `.github/workflows/cascade-ai-github-intermediate.md` (and their `.lock.yml` files); the three AI edges of the preset `sdlc.yaml` that point at `johnhain-msft/portfolio`; and the tests under `tests/s4/` that prove them. It honours three contracts of `plan.md` §5: C4 (SPEC-01 renders the workflows and the immutable-gate policy; this spec defines what they must do and enforce at runtime) [F82], C7 (SPEC-03 dispatches the workflows asynchronously and owns `src/update-poll-state.mjs`; this spec owns the three helpers and the dispatched run lifecycle) [F83] and C9 (the adaptation pull request on the downstream `portfolio`) [F84]. Each dispatched run keeps its `pre-agent-steps:` strictly read-only on the `portfolio` checkout and records `BASE_SHA` and drift reports under `/tmp/gh-aw/agent/` [F60, F61]; lets the agent edit only files in the workflow's exclusive `allowed-files` allowlist [F68]; runs the deterministic bump, accept and build commands and commits their outputs before `create_pull_request`, which packages the agent's commits as a git bundle [F66]; and in `post-steps:` refuses any patch that touches locked rule, auth, runtime or sandbox files or alters a byte-locked test block, rebuilds, checks that the tree is clean and runs the five portfolio checks [F10], so that `safe_outputs` can open one pull request that a human must review and merge (`auto-merge: false` [F69]). For an operator who points the orchestrator at a downstream repository, this is what turns an upstream change into one reviewable pull request that cannot weaken the downstream repository's own guard rails. The engine code is repository-agnostic; the portfolio fleet is data in `sdlc.yaml`. Twelve claims about local `portfolio` files and scripts remain open in §4 and gate the criteria that depend on them.

### Non-goals
- No always-on webhook server, external database or non-GitHub compute: every S4 job runs on GitHub Actions and the three helpers are plain Node.js scripts.
- No automated pull-request merging: `auto-merge` is forbidden on every `safe-outputs.create-pull-request` block and CLI flow of this stream (`"auto-merge": false`, a documented option [F69]); every adaptation pull request needs an explicit human review and merge.
- No automated regeneration of `/pipeline-showcase/media/pipeline-demo.svg`: the portfolio README names no command, npm script or script file for its capture [F22, F34]; when `RUNS` ids change, the pull-request body flags the SVG for manual re-stitching.
- No automatic bump of `gh_aw_schema_version` and no editing or recompiling of `.github/workflows/*.lock.yml` inside `ms-mfg-community/day-in-the-life-copilot-lab`: every `upstream/<repo>` checkout is read-only for S4.
- No Azure Container Apps or sandbox infrastructure change and no live Azure entitlement test (`npm run test:live -w server`): the portfolio README says that local tests do not prove live allocation, ingress, deletion or Copilot authentication [F26], and describes the hosted Studio model [F16].
- No shipping of customer-specific authoring tools from `githubschool/gh-github-intermediate-template` (the portfolio README says they are not shipped [F54]) and no rewriting of upstream lab prose.
- Stream boundary: SPEC-01 (S1) owns `schemas/sdlc.schema.json`, the rendering of `sdlc.yaml` by `src/reconcile.mjs`, the compiled workflow templates, the `on.bots` allowlist and the `allowed-files` policy (C4 sender); SPEC-03 (S3) owns the dispatch trigger, correlation id generation, `src/update-poll-state.mjs` and every `SDLC_SYNC_STATE_<SLUG>` variable (C7 sender); SPEC-02 (S2) owns drift audits and `OQ37`; SPEC-05 (S5) owns bootstrap, App registration and variable and secret provisioning; the downstream `portfolio` owns `experiences/**`, `public/**`, `apps/lab-studio/**` and its pull requests (C9 receiver).
- This spec resolves no open question: every claim in §4 is carried as a gate on named criteria and none is asserted.
