## 1. Objective and non-goals

### Objective
Stream S5 turns a fork or copy of the repository `mfg_msft_ai_sdlc` into a running, self-reconciling AI SDLC orchestrator with one command, and lets an operator point it at any further repository afterwards: once this spec is implemented an engineer runs `node bin/sdlc-bootstrap.mjs` once and later `node bin/sdlc-onboard.mjs --repo <owner/repo-or-path>` (or dispatches `.github/workflows/sdlc-onboard.md`) for each new repository. The stream produces these repository artifacts: `aw.yml`, the `gh-aw` package manifest, and a package `README.md` with consumer install commands [F10]; `bin/sdlc-bootstrap.mjs`, `bin/sdlc-onboard.mjs` and their modules under `bin/lib/`; `schemas/bootstrap-summary-report.schema.json`; and the suites under `tests/s5/`, which include the tests of `.github/workflows/sdlc-onboard.md` and its compiled lock file as rendered by SPEC-01 (`src/reconcile.mjs` is their only writer). The bootstrap CLI first verifies that the local `gh-aw` is at least `1.0.1`, a release newer than the `0.85.4` fix for `GHSA-8h78-hpm7-29gg` [F5, F6]; registers a least-privilege GitHub App through the three-step manifest flow, in which a loopback page posts the manifest, GitHub redirects back with a temporary code and the CLI exchanges that code [F24, F49]; guides and verifies installation across the target user and organization accounts [F20, F21]; creates the `APP_CLIENT_ID` Actions variable and the create-if-missing `SDLC_SYNC_STATE_<SLUG>` variables [F56, F61]; encrypts the App private key and the engine credential locally as libsodium sealed boxes before upload [F39, F44, F46]; optionally disables duplicate in-repo schedules on operator-owned upstream repositories; hands `sdlc.yaml` to stream S1 for validation and `gh aw compile --strict --purge --json` [F7, F8]; and finishes with `gh aw validate` and `gh aw doctor` readiness checks. The onboarding CLI inspects a target repository and writes validated `projects[]` and `dependencyEdges[]` entries plus `instructions/<projectKey>.md` to `sdlc.yaml`. The spec honours contract C1 of `plan.md` §5, where S5 sends `BootstrapReconcileRequest` to S1 and consumes `ReconcileResult` [F60], and contract C10, where `external:operator` invokes S5 and receives a `BootstrapSummaryReport` [F61]. For an operator this means that pointing the orchestrator at a repository takes one command and one browser confirmation, needs no webhook server or database, and never places a credential in a file, a command-line flag or a log; the engine code stays repository-agnostic and the preset fleet remains `sdlc.yaml` data owned by SPEC-001.

### Non-goals
- **No server or database infrastructure.** No always-on webhook server, external database or non-GitHub compute: the only server S5 runs is the short-lived loopback listener of a bootstrap run, and the manifest it posts registers a hook that is not active (`hook_attributes` with `active: false` [F50]).
- **No automated merging.** `auto-merge` is forbidden on every `safe-outputs.create-pull-request` handler and CLI flow, including the pull request opened by `.github/workflows/sdlc-onboard.md`; every automated pull request needs explicit human review and merge.
- **No `pipeline-demo.svg` regeneration.** `/pipeline-showcase/media/pipeline-demo.svg` is not regenerated from live Playwright screenshots of GitHub Actions UI runs.
- **No schema-version bump and no upstream lock-file edits.** `gh_aw_schema_version` is not bumped, and `.github/workflows/*.lock.yml` inside `ms-mfg-community/day-in-the-life-copilot-lab` is neither edited nor recompiled; S5 writes no file, branch, commit or pull request on any upstream repository, and its only upstream-side mutation is the opt-in disabling of explicitly listed workflows (AC31).
- **No Azure infrastructure.** No Azure Container Apps runtime infrastructure, no `Microsoft.App/sandboxGroups` Bicep or Terraform, and no live Azure entitlement tests (`npm run test:live -w server`).
- **No customer-specific tooling and no lab-prose rewriting.** Customer-specific authoring tools from `githubschool/gh-github-intermediate-template` are not shipped and upstream lab prose is not rewritten.
- **Stream boundary.** SPEC-001 (S1) owns `schemas/sdlc.schema.json`, `sdlc.yaml` including the preset fleet data, `src/reconcile.mjs`, `.github/workflows/aw.json` and every rendered workflow policy; SPEC-002 (S2) owns the drift workflows and the open-pull-request deduplication that `C5` defines; SPEC-003 (S3) owns `cascade-router.yml` and is the sole writer of existing `SDLC_SYNC_STATE_<SLUG>` variables; SPEC-004 (S4) owns the AI-adaptation engine. S5 consumes their artifacts and never edits them.
- **Deliberate narrowings.** S5 writes Actions variables and secrets at repository scope on the central orchestrator repository only, because the routes that contract C10 names are repository-scope routes; it adds no `--dry-run` flag (the `dryRun` field of C1 is set only by S5's own code, AC34); and it persists the App private key nowhere except in the encrypted repository secret.
- **No open question is resolved here.** `OQ33`, `OQ44`, `OQ49`, `OQ50` and `OQ51` are carried in §4, the criteria they gate are marked `(gated by OQ<n>)`, and none of their claims is asserted in §1 or §2.
